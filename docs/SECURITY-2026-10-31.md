# SSHTunnel 1.5.1 — DEP-03 수정·검증 결과

작성일: 2026-10-31 (KST)

담당 저장소: OnTechnologyCo/SSHTunnel. 작업 시작 커밋은 감사 기준과 같은
`2c42ae4a5d586b7831f04de97650d780cdf189e0`이며 사용자 변경이 없는 상태에서 시작했습니다.
애플리케이션 Go 소스, 인증 정책, 주소 할당 방식, 데이터 형식은 변경하지 않았습니다.

## 원인과 변경

기존 go.mod는 Go 1.26.0 이상을 허용했고, 개발 PC와 배포 EXE는 Go 1.26.1을
사용했습니다. `Build.ps1`은 PATH의 Go를 사용했으며 `Build-Installer.ps1 -SkipBuild`는
이전 실행 파일도 그대로 패키징할 수 있었습니다.

- `.go-version`과 `go.mod`를 1.26.10으로 일치시켰습니다.
- 두 빌드 스크립트는 해당 버전의 `GOTOOLCHAIN`을 명시하고 실행 후 기존 환경을 복원합니다.
- `scripts/Go-Toolchain.ps1`은 버전 설정 일치 여부와 EXE의 실제 Go 빌드 버전을 검사합니다.
- 설치 파일은 재빌드를 생략해도 EXE와 포함 SDK의 버전을 검사합니다.
- 배포 ZIP/설치 파일에 `build-info.txt`를 포함하고 SDK에 패치 최소 버전을 포함합니다.
- Windows/Linux GitHub Actions에서 테스트·vet·빌드·govulncheck를 실행하도록 추가했습니다.
- 앱/설치 파일 버전은 1.5.1이며 기존 AppId와 데이터 경로는 유지합니다.

공식 자료를 확인한 시점에 최신 안정 계열은 1.27.3, 기존 1.26 계열의 최신 패치는
1.26.10이었습니다. 이번 작업에서는 메이저/마이너 계열을 바꾸지 않고 패치를 적용했습니다.

전체 기존 테스트에는 HTTPS 왕복, 인증서 교체, 잘못된 인증키 거부, 다른 계정의 주소
예약 탈취 거부, 손상된 호스트 키·식별키·주소 저장소 보존도 포함됩니다.
시험 계정·키·인증서·서버는 임시 디렉터리와 로컬 수신 포트에서 생성했습니다.
운영 서비스에 공격 요청을 보내거나 운영 계정·고정 주소·정상 키를 초기화하지 않았습니다.

## 남은 경고와 범위 제한

`GO-2026-5932`는 `golang.org/x/crypto` 모듈 안의 사용하지 않는 `openpgp` 패키지에 대한
경고입니다. 공식 DB는 수정 버전 없음으로 표시합니다. `go list -deps ./...`에 openpgp가
없고 심볼/패키지 검사에서도 도달 경로가 없습니다. 이를 수정 완료로 숨기거나 전체
모듈에 경고가 없다고 보고하지 않습니다. SSH/ACME에 필요한 x/crypto는 유지했습니다.

이 검증은 전체 Git 이력이나 실제 침해 여부에 대한 감사가 아닙니다. 실제 운영 PC의
설치·서비스 재시작과 외부 SDK 내장 프로그램의 재빌드는 이번 작업에서 수행하지 않았습니다.
서버를 업데이트해도 이미 배포된 외부 앱의 Go 런타임은 자동 교체되지 않습니다.

## 업그레이드

서버를 종료하고 1.5.1 설치 파일로 업데이트한 뒤 같은 데이터 폴더로 실행합니다.
기존 계정, 설정, SSH 호스트 키, 주소 예약 파일과 클라이언트 식별키를 유지하세요.
별도 데이터 마이그레이션은 필요하지 않습니다. SDK 내장 앱은 패치된 Go로 다시 빌드해야 합니다.
이전 바이너리/모듈 경고를 피하려고 인증 검사를 끄거나 주소를 새로 발급할 필요가 없습니다.
